# Security Policy

## Supported versions

Security fixes are provided for the latest published release. Experimental
container profiles are supported only to the extent stated in their release
notes and are not promoted to the default deployment without live acceptance.

## Reporting a vulnerability

Use GitHub Private Vulnerability Reporting for this repository. Do not open a
public issue containing exploit details, credentials, hostnames, request logs,
or operational evidence.

Reports should describe the affected version, trust boundary, reproduction,
impact, and any known mitigations. Never attach real tokens, private keys,
OAuth artifacts, generated gateway-key maps, or credential caches.

The project does not use a personal email address as its security intake.
