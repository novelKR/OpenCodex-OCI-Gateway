## What changed

- `CFBundleVersion=1003` corrects the standalone `install-relay.sh` compatibility boundary. The immutable rc.7 and rc.8 releases use signed manifest revision 5, but their tagged standalone installer accepted only revisions 1, 2, and 4 and therefore stopped before installing a fresh or Linux revision-5 release.
- The standalone installer now accepts both revision 4 and revision 5 component manifests. Revision 5 verifies the signed stable/preview channel against strict SemVer, validates the strict minimum-updater version, binds `trust_key_id` to the DER fingerprint of the separately supplied Ed25519 public key, and requires the exact five-artifact and notices shape.
- The revision-5 macOS artifact additionally requires the exact production bundle identity, ad-hoc signing mode, minimum macOS version, integration protocol 1, and helper protocol 1. A macOS install rejects a host below the signed minimum before downloading or staging the app.
- Unknown or missing fields, non-canonical JSON or duplicate fields, malformed strict SemVer, a mismatched channel or trust-key ID, unsupported protocol values, malformed checksums and URLs, and an unexpected component/file matrix fail closed before persistent Relay state changes.
- After the new contract checks pass, revision 5 uses the same lifecycle reservation, routing-controller transaction, atomic `current` selection, service activation witness, and rollback path as revision 4. Revision 1 and 2 remain available only through their existing legacy rollback behavior.

## Safety boundaries

- This release does not change the rc.8 app update UI, Finder/Gatekeeper handoff, runtime-upgrade transaction, privileged Helper policy, user routing/config/credentials, or OCI/Cloudflare deployment state.
- The rc.7 and rc.8 app assets remain valid and immutable. Use the rc.9 tagged installer for a standalone revision-5 install; no prior release is edited or republished.
- The installed app remains ad-hoc signed with Hardened Runtime, no Team ID, and no notarization. App installation and Gatekeeper approval remain explicit user actions, and Relay restart remains a separate approval.
