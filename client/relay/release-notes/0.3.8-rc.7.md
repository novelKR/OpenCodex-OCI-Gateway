## What changed

- Release publication now uses strict manifest compatibility revision 5 and `CFBundleVersion=1001`. The signed contract adds the release channel, minimum updater and macOS versions, trust-key ID, and integration/helper protocol versions while retaining the exact eight-asset and signed app-digest contract.
- A verified `update_available` result can now be downloaded only after the user selects **Download and Verify**. The bundled `opencodex-relayctl release stage` command re-fetches the exact immutable release and verifies the release ID, tag, channel, manifest signature and digest, app digest, strict SemVer ordering, and compatibility requirements again.
- Staging uses an owner-only Application Support root, an exclusive lock, release-ID/manifest-digest directory identity, and a strict schema-version-1 receipt. A complete matching stage may be reused only after its receipt, archive, app bundle, and fingerprint all pass revalidation.
- ZIP processing now rejects traversal and absolute paths, empty components, duplicates and case-fold collisions, links and special files, multiple roots, oversized archives or expansion, excessive path/file counts, and excessive compression ratios before accepting the single `OpenCodexRelay.app` root.
- The extracted app must have the exact production bundle ID and version, a newer numeric build, the expected arm64 executable set with no unexpected executable files, valid nested ad-hoc signatures, no Team ID, Hardened Runtime, the expected helper CDHash binding, and the byte-identical embedded tracked release key.
- Swift and Go share the stage receipt fixture. Unknown or duplicate fields, drift from the selected candidate, partial staging, receipt tampering, and a changed exact release fail closed.

## Finder-managed installation and safety

- The app re-runs staging validation immediately before handoff, applies Foundation quarantine metadata, reads the security-relevant metadata back, and reveals the verified app in Finder. Quitting is a separate user confirmation.
- After quit, the user copies or replaces the app in Applications and opens that exact copy manually. If macOS blocks it, use the normal **System Settings → Privacy & Security → Open Anyway** flow. Keep the previous app manually until the replacement launches successfully.
- This update path does not remove quarantine, invoke `spctl`, disable Gatekeeper, overwrite `/Applications`, self-relocate, relaunch, promise an atomic app-level rollback, restart the resident Relay, or update the privileged Helper.
- The Finder handoff is intentionally separate from the first-install relocation card. An ad-hoc app can launch under App Translocation before Gatekeeper approval, so a self-relocation transaction cannot safely prove a launch from its final Applications path.
- Lifecycle-busy and recovery-required states block staging and handoff without changing the current app or resident Relay. A Helper version mismatch continues to report `manual_update_required` and requires its separate administrator-approved workflow.
