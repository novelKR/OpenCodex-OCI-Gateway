## What changed

- Local OpenCodex now presents installation inspection and verified Native Codex return/removal as its primary task. When the routing binding is exactly absent, the page keeps standalone Native inspection available without requiring Relay setup; a ready binding continues to use the integrated inspection path, while unsafe, invalid, preview, helper-unavailable, and recovery states remain fail-closed.
- Remote Gateway setup is separated into a secondary card that appears only while Relay preparation is required. The page handles that exact first-run warning inline, without hiding security or recovery errors, and no longer shows an ambiguous unknown Relay status when no binding exists.
- The privileged-helper setup sheet now keeps the reviewed installer command bound to the state that opened it. **Check helper status** shows progress, preserves the command when the same install/update remains necessary, and invalidates the command immediately if the lifecycle state changes.
- A successful helper check replaces the command and diagnostic codes with a persistent success result, the verified helper version, and a clear **Done** action. The app does not close the result automatically, so the administrator can confirm what was verified.

## What to validate

1. With no routing binding, confirm **Local OpenCodex management** appears first, offers installation inspection, and keeps **Remote Gateway connection** as a separate secondary card.
2. Confirm a ready binding uses integrated discovery, while unsafe, invalid, preview, helper-unavailable, and recovery states do not expose installation inspection or removal actions.
3. In the helper install or update sheet, confirm status checking displays progress and that an unchanged requirement retains the original reviewed command.
4. After the matching helper becomes ready, confirm the sheet hides the command, copy action, and failure diagnostics; shows the verified helper version; and remains open until **Done** is selected.
5. If helper state changes to recovery or another lifecycle phase, close the sheet and use the refreshed maintenance-card action rather than any command copied earlier.

The macOS app and its privileged helper are version-bound. Replacing the app does not update the administrator-installed helper. Complete the separately approved helper update shown in **App Information** before relying on Homebrew removal protection; until then, `update_required` is the expected state.
