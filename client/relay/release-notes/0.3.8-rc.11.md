## What changed

- `CFBundleVersion=1005` ships the Public CI and macOS Keychain compatibility hardening merged after `0.3.8-rc.10`.
- Every external GitHub Action used by CI, CodeQL, Relay release, experimental container release, and teardown-profile audit is pinned to a reviewed Node 24-capable release by its full commit SHA and audited version comment. A shared publication policy rejects mutable or shortened references, unreviewed Action repositories, and versions below the reviewed major floor; bounded weekly Dependabot PRs can propose later updates without bypassing required checks.
- The teardown-profile audit now provisions the reviewed Go 1.24 toolchain explicitly instead of relying on the hosted macOS image PATH.
- The production app confines the deprecated file-Keychain trusted-application ACL inspection to the internal `OpenCodexRelayLegacyKeychainACL` C compatibility target. Swift and unrelated C code remain warning-clean, while the credential store keeps the exact current-user default Keychain, application executable, and `/usr/bin/security` trust requirements.
- Isolated CI coverage creates temporary default and secondary Keychains, verifies search-list isolation plus credential create, replace, ACL repair, and readback, and requires exact default/search-list restoration before cleanup.

## Safety boundaries

- The C target is a narrow compatibility boundary for the existing ad-hoc distribution; it is not a migration to the Data Protection Keychain. The deprecated file-Keychain ACL remains in use until a separately reviewed Developer ID, provisioning, access-group, and credential-migration design is adopted.
- ACL inspection and post-write verification remain bound to the same default-Keychain path witness. An adapter error, default-Keychain change, missing application executable, lifecycle conflict, or ACL mismatch that cannot be repaired remains fail-closed; no broader ACL fallback is introduced.
- This release does not change credential service or account selection, manifest revision 5, the v2 Ed25519 trust root, minimum updater `0.3.8-rc.6`, integration protocol 1, Helper protocol 1, receipt or binding schemas, runtime APIs, Relay routing, or OCI/Cloudflare deployment state.
- The privileged Helper remains exactly version-bound to the application bundle. Replacing the app can therefore report `update_required`; an administrator-approved Helper update remains a separate action.
- The resident Relay runtime upgrade remains a separate journaled operation. Publishing or replacing the app does not update that runtime, modify `/Library` or Homebrew, prepare Relay integration, change credentials, switch Codex routing, or remove Local OpenCodex.
- The app remains ad-hoc signed with Hardened Runtime, no Team ID, and no notarization. Finder replacement and any required Gatekeeper approval remain explicit user actions.
