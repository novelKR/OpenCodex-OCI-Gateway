## What changed

- The production macOS app now checks the public `novelKR/OpenCodex-OCI-Gateway` GitHub Releases channel through the bundled `opencodex-relayctl release check` command. Stable is the default and preview remains an explicit opt-in.
- Automatic checks are enabled by default for production, start 5–15 minutes after launch, and repeat at most every 24 hours. Local-development builds never make automatic update requests; manual checks remain available.
- App Information, Settings, and the menu-bar quick menu show the selected channel, last check, bounded status, exact verified release link, and a candidate-specific dismissible badge. The app does not request Notification Center permission.
- Release discovery now uses bounded pagination and strict SemVer rather than GitHub list order, re-fetches the selected immutable release by ID, and verifies the exact eight-asset set, Ed25519 manifest signature, and signed macOS app digest before reporting an available update.
- Go and Swift share schema-version-1 fixtures. Unknown fields, duplicate fields, unknown enum values, malformed versions, unsafe local trust-key paths, oversized responses, and invalid release contracts fail closed.

## Compatibility and safety

- This is the first updater-capable bootstrap and remains release-manifest compatibility revision 4 with `CFBundleVersion=1000`. Existing `0.3.8-rc.5` users must install it manually.
- This release is notification-only. It does not download, stage, install, relaunch, restart Relay, update the privileged Helper, remove quarantine, bypass Gatekeeper, or mutate user routing, credentials, OCI, or Cloudflare state.
- GitHub API metadata is candidate-discovery input, not a trust root. The tracked Ed25519 key embedded in the app verifies the manifest; that signed manifest binds the macOS ZIP digest.
- Expected remote states are returned as bounded JSON without interrupting the current app or resident Relay. Invalid local arguments and trust inputs remain command errors.
- The app remains ad-hoc signed with Hardened Runtime and is not Developer ID signed or notarized. First launch of a downloaded copy still depends on the user's normal macOS Gatekeeper approval.
