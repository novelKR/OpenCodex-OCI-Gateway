## What changed

- A missing routing binding is now presented as a first-run setup warning instead of a broken-installation error.
- Local OpenCodex shows a same-window shortcut to **Settings → Connect a self-hosted server** and keeps discovery unavailable until the user Relay integration is ready.
- Settings exposes only the action valid for the current state: **Prepare Relay**, **Recover setup**, or the normal **Test connection** and **Apply** controls.
- A recovery-required response is re-inspected before recovery is enabled, preventing stale setup state from exposing the wrong action.

## What to validate

1. Confirm the missing-integration notice is orange and the Local OpenCodex page shows the Settings shortcut instead of discovery.
2. Confirm the shortcut selects Settings in the same Control Center window without starting preparation or recovery.
3. Confirm `integration_required` exposes only **Prepare Relay** and `recovery_required` exposes only **Recover setup**.
4. Confirm an existing Codex configuration is unchanged until the user explicitly switches Codex routing.

The macOS app and its privileged helper are version-bound. After replacing an older app bundle, run the fixed helper-installer command shown in **App Information** and complete the separate administrator approval before relying on Homebrew removal protection.
