## What changed

- `CFBundleVersion=1002` adds a separate schema-version-1 `integration upgrade` namespace without changing the existing `integration apply/recover` contract. `inspect` reports only `not_integrated`, `current`, `upgrade_available`, `recovery_required`, or `incompatible`, with exact installed and bundled runtime versions and combined Relay/relayctl digests.
- Runtime apply requires the exact inspected state digest and `--confirm-relay-restart`. It holds the shared lifecycle writer lock, verifies both bundled executables, stages a full-digest versioned runtime, snapshots config/routing/binding/Codex-config identity and ownership, writes a durable upgrade journal, and atomically switches only `current` and the user LaunchAgent.
- Success requires loopback readiness for the unchanged routing generation and phase, plus the actual launchd PID executable path and file digest matching the new bundled Relay. A durable success witness is written before the journal is removed; the previous runtime is retained.
- A failed restart or readiness/invariant check restores the previous `current` target and LaunchAgent, restarts and verifies the previous Relay, removes only a newly created failed runtime, and leaves the journal in place if rollback cannot be proven.
- `recover` uses the strict journal phase and exact file identities to choose either verified forward completion or rollback. It never removes the integration, reapplies config/routing, reads or changes credentials, or installs/replaces the privileged Helper.
- The app inspects runtime convergence on launch and shows **Finish Relay Update** in Settings and App Information. A restart warning and explicit confirmation are required; lifecycle and recovery states disable the mutation controls. English and Korean UI use the same strict Go/Swift fixture-backed state contract.

## Safety boundaries

- App installation remains the rc.7 Finder-managed, quarantined, user-approved flow. Runtime convergence starts only after the new app has launched from an approved Applications location.
- The privileged Helper retains its exact-CDHash and separate administrator approval contract. A Helper version mismatch continues to appear as `manual_update_required`; runtime upgrade does not attempt to fix it.
- User config, routing generation and phase, credential account boundary, file ownership, Homebrew state, and OCI/Cloudflare deployment remain outside the mutation set.
- A runtime-upgrade journal, integration/app-relocation/routing/removal recovery journal, lifecycle writer conflict, stale expected digest, newer installed runtime, malformed current target, or ambiguous file identity fails closed.
