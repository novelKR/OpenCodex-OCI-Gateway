## What changed

- When `routing-binding.json` is exactly absent, Local OpenCodex discovery and safe removal no longer require Relay setup. The removal flow first restores and verifies the standard Native Codex configuration and `clientIntegrations.codex=false`, then removes the verified OpenCodex package and managed integrations while preserving data by default. Eligible, explicitly selected data may still be moved to Trash after the existing second confirmation.
- The standalone Native path uses only the standard `~/.codex/config.toml` and canonical app-managed Relay/OpenCodex roots; ambient `XDG_CONFIG_HOME` or `OPENCODEX_HOME` overrides are not eligible for automatic removal. It does not connect to a remote Gateway or require Gateway credentials, a running Relay service, Relay configuration, a LaunchAgent, or Keychain entries.
- A ready routing binding continues to use the existing integrated removal path. Unsafe, invalid, preview, partial-setup, and recovery states remain fail-closed, as do custom `CODEX_HOME`, local-Relay, mixed, foreign, and unmanaged Codex configurations.
- Standalone and integrated removal share lifecycle exclusion and context-bound recovery records, preventing Relay preparation or a recovery from being mistaken for the other removal mode.
- On macOS, production and local-development source install/uninstall transactions now hold an owner-only lifecycle reservation across routing, LaunchAgent, binding, and runtime mutations. Service helper mutations are internal to that reservation, incomplete rollback or teardown retains its marker and recovery workspace, and lock descriptors cannot leak into executed package processes. A pre-capability legacy artifact is a rollback target only when a lifecycle-capable installed helper can coordinate it; a fresh legacy macOS install fails before persistent writes.
- A completed standalone removal retains a replayable terminal journal and emits its exact `terminal_receipt_digest`. The app durably checkpoints that digest before calling `discover-open-codex-native --acknowledge-terminal-receipt-digest`; bare discovery or a different digest cannot retire the record. The matching acknowledgement independently revalidates the fixed boundary and package absence, retires only that record, and is idempotent if the app exits before clearing its local checkpoint. Relay Apply and Recover refuse retained or malformed standalone journals.
- OpenCodex data remains preserved by default. When an eligible standalone candidate exposes selective Trash, only explicitly selected items may be moved after the existing second confirmation and a fresh Native-boundary check. Homebrew-protected candidates still require the separately approved privileged helper before package removal.

## What to validate

1. With no routing binding, no partial canonical app-managed Relay setup, no pending removal recovery, and the normal trusted Desktop, managed-runtime, and bundled-relayctl safety prerequisites satisfied, confirm the Local OpenCodex page can discover an eligible installation and offers the Native-return removal action while retaining the separate Relay setup warning.
2. Confirm review identifies the standard Native Codex configuration and defaults to preserving OpenCodex data; if selective Trash is available, confirm it requires a separate item selection and second confirmation.
3. Confirm standalone review and inspection do not request a server URL or Gateway credentials and do not create or modify Relay configuration, binding, LaunchAgent, Keychain, or remote settings.
4. Confirm an unsafe or invalid binding, setup recovery, a custom `CODEX_HOME`, or mixed, foreign, unmanaged, or local-Relay Codex configuration blocks automatic removal before Desktop exits or a package command starts.
5. With a ready binding, confirm the existing integrated removal path and its routing checks remain in effect.

The macOS app and its privileged helper are version-bound. After replacing an older app bundle, run the fixed helper-installer command shown in **App Information** and complete the separate administrator approval before relying on Homebrew removal protection.
