## What changed

- Standalone Native discovery now reports a bounded reason when a detected OpenCodex package cannot be removed automatically. The Local OpenCodex page shows **Manual removal required** with the exact safe reason instead of an unexplained disabled action.
- **Copy diagnostic details** copies only package version, package manager, and the bounded reason code. It excludes paths, fingerprints, usernames, credentials, and Relay state.
- The observed OpenCodex `2.22.0` installation closure is enabled as `npm_2_22_0_darwin_arm64_v3` only after all 99 package identities and official npm `sha512` integrities were pinned, two isolated roots reproduced the exact closure, all 11 critical modules matched the existing `2.22.0` review, and the Relay teardown adapter dry-run preflight succeeded.
- New automatic-removal profiles must include a registry-backed review manifest. macOS CI reconstructs every manifested profile twice; a missing manifest for any profile added after the closed historical baseline fails the build.
- A weekly read-only audit repeats profile reconstruction and reports a new stable upstream version as `unsupported` in the job summary. It never changes profiles or creates issues automatically.

## Compatibility and safety

- Swift accepts standalone Native discovery schemas 1 and 2. Schema 1 manual candidates receive the generic `verification_unavailable` explanation; schema 2 requires one of the bounded reason codes.
- Removal receipts and inventories remain schema 1. The runtime API, routing binding, privileged-helper receipt, and release manifest revision 4 are unchanged.
- Complete installation-closure verification remains fail-closed. A changed transitive file, executable mode, symlink, critical module, unsupported version, incomplete execution proof, unapproved package manager, or unverified identity does not gain automatic-removal authority.
- Helper lifecycle and Relay routing are displayed independently; a ready helper or a missing Relay binding does not make an unreviewed package closure eligible.

## What to validate

1. With the reviewed `2.22.0` v3 closure, confirm Local OpenCodex inspection offers the existing Native-return removal wizard.
2. With an unsupported or changed fixture, confirm the page shows **Manual removal required**, the correct bounded reason, and sanitized diagnostic copy output.
3. Confirm helper and Relay status changes do not change the package-profile decision.
4. Confirm no actual Local OpenCodex removal occurs during release validation.

The macOS app and privileged helper remain version-bound. Replacing the app does not update the administrator-installed helper; an existing `0.3.8-rc.3` helper reporting `update_required` after the app moves to `0.3.8-rc.4` is expected and requires separate administrator approval.
