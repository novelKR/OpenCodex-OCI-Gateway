## What changed

- The reviewed `2.22.0` v3 teardown profile now uses the same depth-first lexical closure order as the production Go runtime. This corrects the `0.3.8-rc.4` verifier-only digest ordering mismatch that kept the reviewed installation fail-closed as `unreviewed_package_closure`.
- Profile review now performs two isolated, scripts-disabled npm global installs from the official registry using the manifest's reviewed publication-time cutoff. It verifies all 99 package identities and `sha512` integrities, the complete artifact inventory, critical modules, symlinks, executable modes, and teardown-adapter dry-run preflight.
- The review tool invokes a test-only Go digest bridge and requires its closure digest to match both independent npm reconstructions and the committed profile. Python-only agreement is no longer sufficient to approve a profile.
- macOS CI provisions the repository's Go 1.24 toolchain before profile reconstruction, so the runtime-parity check is enforced on every relevant Public pull request and `main` build.

## Compatibility and safety

- Complete installation-closure verification remains fail-closed. This release does not allow an observed local hash directly and does not weaken file, mode, symlink, module, identity, or package-manager checks.
- `0.3.8-rc.4` did not authorize an unsafe removal: its ordering mismatch rejected the otherwise reviewed closure. This release restores automatic eligibility only for the independently reproduced and runtime-identical `2.22.0` v3 profile.
- Standalone Native discovery schema 2, removal receipts, the runtime API, routing binding, privileged-helper receipt, and release manifest revision 4 are unchanged.
- New stable upstream versions remain `unsupported` until a complete review manifest and matching adapter are added through the same review process.

1. Inspect the reviewed Homebrew/global-npm OpenCodex `2.22.0` installation and confirm it reports `automatic_removal_reason=eligible` without changing Codex configuration or removing the package.
2. Change one transitive file, mode, symlink, or critical module in a fixture and confirm discovery remains manual-only with the corresponding bounded reason.
3. Confirm helper state and Relay binding presence do not affect package-profile eligibility.
4. Confirm no actual Local OpenCodex removal or `/opt/homebrew` mutation occurs during release validation.

The macOS app and privileged helper remain version-bound. Replacing the app does not update the administrator-installed helper; an existing `0.3.8-rc.4` helper reporting `update_required` after the app moves to `0.3.8-rc.5` is expected and requires separate administrator approval.
